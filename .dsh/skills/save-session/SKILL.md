# 会话断点存档（/save-session）

用户说"保存当前对话内容到 session"、"记录当前进度 下次直接开始"、"先保存会话再干别的"、"会话先存档"、"/save-session"、"到点了存档"等 → 触发本 skill。

目标：把当前对话的进度、命令、结论固化到项目文档，保证下次会话从断点无缝续跑（以"⏸️ 会话断点存档"段格式为准，持续收敛：少重复、可扫读、最新优先）。

## 触发与意图

| 用户输入 | 行为 |
|---------|------|
| `/save-session`（无参数） | 盘点本次会话全部工作 → 按项目写入断点存档 |
| "保存当前对话内容到session" / "记录当前进度" / "下次直接开始" / 会话中途用户要退出 | 自动识别，同上（等价于无参数） |
| "继续" / "恢复" / "接着上次来" | 走**恢复流**（§恢复流），不是存档 |

## 可配置项（CLAUDE.md）

项目在 `CLAUDE.md` 声明以下配置覆盖默认行为（未声明用默认值）：

```markdown
## Session 配置

- ops.root: ops/           # 断点段与 raw-log 根目录，默认 ops/；已配置 ops.root（如装了 ops-playbook）则直接复用
- session.projects:        # 可选，多子项目/上下文名列表，用于 /save-session 补全与区分；未配置则整个仓库为一个项目
- session.tz:              # 可选，与外部服务器日志统一时区口径（如 Asia/Shanghai）；默认本地时间
```

## 存档流程（六步）

### 0. 存档自检（无实质新内容则不写）

写盘前先判断本次会话是否值得存档：
- `git status --short` + 回顾自**上一条断点段日期**起，本次会话有无：新终端输出、新阶段进展、新坑、新决策
- 若**无任何实质新内容**（纯查询/闲聊/重复劳动）→ 明确告知"本次无新进度，可不存档"，**终止流程**，不硬写一段
- 有 → 继续以下步骤

### ① 会话工作盘点

回顾当前对话全部工作，按主题分组，标注：
- ✅ 已完成（含结论、脚本 git hash、核验口径）
- ⚠️ 有保留/中途失败（如实记，不美化）
- ⬜ 未做的待办

### ② 断点生命周期处理（写新段前必做）

在写新断点段之前：
1. 读取日志中**最新一条 ⏸️ 断点段**
2. 若有 → 在其标题行下插入一行（只追加不改正文）：
   `> ⏭️ 已续：下一条 <YYYY-MM-DD HH:MM> 断点段为当前进度，本段"恢复点命令"可能已过时`
3. 若无 → 直接写（首次）

> 目的：排空"哪条是最新"的歧义。已打标记的段不再被当作恢复入口。

### ③ 写入 ⏸️ 断点段

在 `<ops.root>/ops-log.md` 日志末尾追加（**标题必须带内容摘要**，让扫描一眼定位卡点）：

```markdown
### ⏸️ <YYYY-MM-DD HH:MM> <一句话内容摘要>（下次 <skill入口> 恢复）

**当前进度**：
- ✅ 完成项（可多条，每条带关键结论/数据）
- ⚠️ 有保留项（如实记）
- ⬜ 未做项

**下次恢复点（第一拍命令模板）**：
（第一拍要执行的命令，含判据/核验口径，如 du 期望值、HTTP 200、状态文案）
```bash
...
```
（判据：xxx → 满足则进入下一步；不满足则检查 yyy）

**后续步骤**：
1. ... 2. ... （按顺序，含每步的关键命令/脚本 git hash）

**环境备忘**（基线+增量，见下）：
- 相关提交：<本次会话提交状态 / 已提交 hash>
- 基线变化：<只列与上次断点段不同的项；无变化写"无"并省略逐条>
- 未变基线（同 <最近一次全量段 YYYY-MM-DD HH:MM>）：<依赖/配置/环境口径等>
- raw-log 指针：raw-logs/<日期>.md §...
```

**环境备忘·基线+增量规则**：
- 首次存档（或基线发生大变化时）→ 写**全量**（脚本/配置路径、环境状态、凭据提示、坑点提醒）
- 后续存档 → **只写本段新增变化**；未变的项一律引用"同 <最近全量段> "，不重复罗列
- 例：
  ```
  **环境备忘**：
  - 相关提交：`abc123`（未提交）
  - 本段变化：依赖装好 venv；配置文件无变化；新增 /pitfall 2 条
  - 未变基线（同 01-05 12:04 段）：venv 路径 /opt/proj-venv、构建工具链版本、密钥由用户每会话提供
  - raw-log 指针：raw-logs/2026-01-05.md §新增段
  ```

### ④ 补录 raw-log

若本次会话用户贴回的终端输出尚未记入 `<ops.root>/raw-logs/YYYY-MM-DD.md` → 补录（遵循 CLAUDE.md 分层精记：证据性内容全文、过程性内容精记，省略处标注）。

### ⑤ 收尾检查

- `git status --short` 检查未入库变更：
  - 有 → 提示：`/checkpoint` 提交推送（存档 ≠ 提交，save-session 只落盘）
  - 无 → 告知工作区干净
- 给用户一句话总结存档位置

## 恢复流（resume）

用户说"继续 / 恢复 / 接着上次"时，**不是存档**，走：

1. 读取**最新一条 ⏸️ 断点段**（标题带摘要；有 `✅ 已恢复` / `⏭️ 已续` 标记则跳过看更早的未标记段）
2. 在其标题行下插入一行：`> ✅ 已恢复于 <YYYY-MM-DD HH:MM>`（只追加，不改正文）
3. 执行该段"下次恢复点"第一拍命令（用户执行→贴 log→见 log 即存）
4. 推进完成后如需存档 → 走上方存档流程（新段会自动把本段标为已续）

## 铁律

- **只追加不覆盖**：日志 / raw-log 永远追加；给旧段打标记也是"追加一行"，不重写已有小节
- **断点段必须含"下次恢复点"命令模板**（带判据）——否则存档不完整，不允许收工
- **标题必带内容摘要**——无摘要不允许收工
- **进度如实**：失败的阶段如实记（矩阵用 ⚠️/❌），不美化
- **不越界处理非本会话项目的数据**：外部/历史项目数据只读（除非任务本身属于该项目）
- **凭据不落盘**：存档中不写密码，只写"密码每会话由用户提供"
- **存档 ≠ commit**：不主动提交推送；用户要求"存档+提交"时提示 /checkpoint
- **不硬存档**：无实质新内容（§步骤 0）不写段；旧断点段不做强制回填改造，仅在"正好被本次续接"时打标记

## 与 /checkpoint 的分工

| Skill | 职责 |
|-------|------|
| `/save-session` | 会话内容落盘（断点段 + raw-log 补录），产出"下次直接开始"命令 |
| `/checkpoint` | 落盘文档提交推送 git（存盘点） |

顺序：`/save-session` → `/checkpoint`（用户常连用；若用户一次说"存档并提交"，先 save-session 再 checkpoint）

## 时间戳口径

- 一律用**本地时间** `<YYYY-MM-DD HH:MM>`（24 小时制）
- 若项目需与外部服务器日志对齐（如跨时区），在 CLAUDE.md `session.tz` 声明统一时区口径
- 历史段里的旧口径时间戳不回填，仅在新段开始用当前口径

## 设计原则

- **格式自一致**：本模板即"⏸️ 会话断点存档"段的唯一格式来源，不依赖任何历史约定
- **少重复、可扫读、最新优先**：断点标题带摘要 + 环境备忘基线增量，保证一眼定位卡点
- **与 ops 工作流共存**：断点段与 ops-log / raw-logs 同根（`ops.root`），不另造一套日志
