# 文档引用审计

检查项目中所有 Markdown 文档与磁盘上实际文件的一致性。发现路径错误、计数偏差、引用过时等问题，按严重程度分类报告，自动修复后提交存档。

## 调用

```
/audit-ref          → 完整审计（收集 → 审计 → 报告 → 修复 → checkpoint）
/audit-ref --dry    → 仅审计 + 报告，不修复，不 checkpoint
/audit-ref --fix    → 仅修复已知问题（跳过审计，直接应用上次报告）
/audit-ref --help   → 显示帮助
```

## 可配置项（CLAUDE.md）

项目可在 `CLAUDE.md` 中声明以下配置来覆盖默认行为：

```markdown
## 审计配置

- audit.exclude: 排除的路径（glob），默认 `.git/`, `node_modules/`, `.claude/`
- audit.skip-fix: 跳过修复的文档列表，这些文档会被审计但不自动修改（如历史记录类文档）
- audit.auto-checkpoint: 修复后是否自动执行 `/checkpoint -y`，默认 `true`
- audit.key-docs: 关键文档清单（至少审计的对象），不声明则按默认规则识别
```

未声明时使用默认值。

## 步骤

### 1. 读取项目配置

读 `CLAUDE.md`，提取 `## 审计配置` 段（如存在），确定：
- 排除哪些路径不扫描
- 哪些文档只审计不修改
- 是否自动 checkpoint
- 关键文档清单

### 2. 建立 Ground Truth

动态扫描项目实际文件结构，获取不可变事实：

```bash
# 列出所有顶层目录（排除 .git）和文件
ls -d */

# 收集所有非排除路径下的文件与目录（递归）
Glob: **/*  （排除用户配置的路径 + 默认排除项）
```

汇总为 ground truth：
- 项目根目录路径
- 顶层目录列表
- 项目关键目录的结构（如 `docs/`、`deploy/` 等下的子目录、计划/日志/参考类文档清单）
- `.claude/skills/` 下所有 skill 名称（如存在）
- 各目录下的文件清单及数量
- 构建完整文件路径集合（用于后续存在性验证）

### 3. 收集待审计文档

```bash
Glob: **/*.md  （排除用户配置的路径 + 默认排除项）
```

得到完整的待审计文档列表。**关键文档必须覆盖**（不限于以下，具体清单可由项目 CLAUDE.md 的 `audit.key-docs` 声明）：
- 根目录 `CLAUDE.md` / `README.md`
- 项目核心目录下的计划/记录类文档（如 `deploy/**/plan.md`、`docs/learn/*.md` 等）
- `.claude/skills/*/SKILL.md`

### 4. 逐文档审计

对每个文档，检查以下四个维度：

**路径存在性**：
- 文档中 `` `path/to/file` `` 或 `[text](path)` 形式的文件/目录引用
- 验证引用目标在磁盘上是否实际存在
- 相对路径以文档所在目录为基准解析
- 绝对路径（以 `/` 或盘符开头）直接验证

**计数准确性**：
- 匹配 "共 N 个"、"N 个文件"、"N 条"、"N 台"、"含 N " 等数量声明
- 对照 ground truth 验证 N 是否准确
- 表格行数与宣称的条目数是否一致

**引用新鲜度**：
- 是否引用了已被删除的文件或目录
- 是否引用了已重命名的路径
- 是否引用了已废弃但文件仍然存在的旧模块（较低优先级）
- 编号/阶段目录的状态与名称是否一致（如已终止/废弃的阶段目录，文档中是否仍描述为进行中）

**语义过时**：
- "新版""旧版""当前""最新""即将""进行中""活跃" 等时间性修饰词
- 对应的实体已删除/变更/终止时，修饰词标记为多余
- 特别关注：进度类文档（plan/进度表）中的"当前进度"、主文档中的"当前活动项目"是否描述最新状态

### 5. 分类报告

按严重程度输出：

| 级别 | 标记 | 含义 |
|------|------|------|
| 🔴 严重 | 路径不存在 | 文档引用的文件/目录在磁盘上找不到 |
| 🟡 中等 | 计数/描述错误 | N 不对、名称不匹配、表格条目数与声明不一致 |
| 🟢 轻微 | 语义过时 | 修饰词多余、项目状态描述过期 |

报告格式：

```
## 审计报告 — YYYY-MM-DD

> 扫描 N 个文档，发现 M 处问题。

### 🔴 严重（N 处）
- **文件**: path/to/doc.md:42
  **内容**: `"`scripts/old.py`"` → 文件不存在
  **修复**: 删除引用，或更新为实际路径

### 🟡 中等（N 处）
- **文件**: path/to/doc.md:15
  **内容**: "共 21 个文件" → 实际 22 个
  **修复**: 改为 22

### 🟢 轻微（N 处）
- **文件**: path/to/doc.md:88
  **内容**: "进行中" → 项目已终止
  **修复**: 更新状态描述
```

### 6. 修复

`--dry` 模式跳过此步骤。

根据报告逐项修复文档：
- 🔴 和 🟡 必须修复
- 🟢 顺手修，不改也行
- `audit.skip-fix` 配置的文档跳过修复
- 用户手动指定的 `--fix` 模式直接应用上次报告中的修复项

修复原则：
- **改文档不改代码**（除非文档暴露了代码 bug）
- 路径引用更新为实际存在的路径
- 计数更新为 ground truth 的实际数量
- 无法确定正确值的，标记 `【待确认】` 而非猜测

### 7. 自动 Checkpoint

- 无任何发现 → 输出 `✅ 文档引用全部一致，无需修复`，跳过 checkpoint
- 有修复且 `audit.auto-checkpoint` 为 `true`（默认）→ 执行 `/checkpoint -y`
- `--dry` 模式跳过

---

## 原则

- **Ground truth 来自磁盘和源码**，不是文档自身描述
- **修复优先改文档**，不改代码（文档出错概率远高于代码）
- **不硬编码项目结构**，一切从磁盘扫描动态获取
- **可配置项通过 CLAUDE.md 声明**，全部有合理默认值
- **不确定的不乱改**，标 `【待确认】` 留给人工判断
- **历史文档谨慎处理**：`audit.skip-fix` 配置的文档仍审计但不自动修改；历史记录类文档（ops-log / changelog 等）只审计路径引用，不审计"下一步""当前状态"等时效性内容——那些是历史快照
- **已知状态标记作为事实保留**：目录名/标题中的 terminated / abort 等已知状态标记，不强制统一修饰或改写
